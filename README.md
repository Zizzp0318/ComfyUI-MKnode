# ComfyUI-MKnode

MK 系列 ComfyUI 自定义节点合集：图像加载 / 选择 / 对比 / 保存、提示词拼接、任意类型切换、图像分块重绘、抠图与清理。

所有节点都在 **`MK节点`** 分类下。

## 节点一览

| 节点 | 说明 |
| --- | --- |
| MK-加载图像 | 加载图像，可按目标总像素等比缩放 |
| MK-图像选择器 | 执行时暂停，手动挑选图像后再继续 |
| MK-图像对比 | 拖动分割线对比图像A/图像B，并把图像A透传给下游 |
| MK-图像裁剪 | 按位置与偏移裁剪图像，输出实际裁剪起点坐标 |
| MK-图像合并（遮罩） | 把覆盖图按遮罩（可扩展/羽化）叠到背景图上 |
| MK-遮罩裁剪 | 按遮罩裁出主体并按四向扩展，输出接缝 / 裁剪图像 / 裁剪遮罩 |
| MK-遮罩是否为空 | 判断遮罩有没有有效内容，输出布尔值（可要求最小有效面积占比） |
| MK-图片背景移除 | 用 RMBG-2.0 / INSPYRENET / BEN / BEN2 抠图，输出透明图 + 遮罩（可合成底色） |
| MK-裁剪恢复 | 把处理过的裁剪图按接缝贴回原图并羽化融合 |
| MK-自适应百万像素 | 按图像实际像素输出百万像素，并夹在你设定的最小/最大区间内 |
| MK-自适应最长边 | 按图像长边输出分辨率（像素），并夹在你设定的最小/最大区间内 |
| MK-提示词拼接 | 把多段提示词按分隔符拼成一条，输入端可动态增减 |
| MK-提示词预设图库 | 文本框 + 「预设图库」面板：左侧分类，右侧图片网格，点图把提示词填入文本框（内置 8763 条写真预设） |
| MK-Minimax H3多参考生视频 | 官方 MiniMax H3 参考生视频的完整复制版，参考图 / 视频 / 音频插槽全部常驻（不用点「+」加槽） |
| MK-多媒体素材加载 | 9 图 + 3 音频 + 3 视频装在一个面板里，执行后打包成一条素材总线 |
| MK-多媒体素材解包 | 把素材总线拆成 18 个素材口，口名与「MK-Minimax H3多参考生视频」的输入口逐字一致 |
| MK-Qwen Image 2.1文本编码器 | 官方 Qwen Image 2.1 文本编码的完整复制版，16 个参考图像插槽全部常驻（不用点「+」加槽） |
| MK-任意切换 | 多路任意类型输入，输出第一个非空值；输入端自动增减、类型自动跟随 |
| MK-Qwen Image 2.1提示词增强 | 用 Qwen 官方 PE 模型把简短描述改写成完整提示词，支持文生图 / 图生图（最多 9 张参考图） |
| MK-显存清理 | 卸载模型 + 清空显存缓存，数据原样透传，每次排队必执行 |
| MK-内存清理 | 收缩文件缓存 / 各进程工作集 / 未使用 DLL，数据原样透传 |
| MK-禁用（忽略）多组老年关怀版 | 把所有分组列成开关，一键切整组启用 / 绕过 / 禁用；自绘大字号面板，可缩放 |
| MK-禁用（忽略）多组青春版 | 同样功能，原生控件界面（每组一个开关 + 设置按钮），无缩放 |
| MK-图像保存 | 保存图像，支持 PNG / JPEG / WEBP |
| MK-图像分块 | 按成品百万像素把图切成模型能一次重绘的小块（可先过放大模型） |
| MK-分块合并 | 把重绘后的分块拼回整图，接缝羽化、保色，并缩放到成品尺寸 |
| MK-Lora加载器 | 给模型加载 LoRA（只影响模型）；可选项支持「无」= 不加载 |

## 安装

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/Zizzp0318/ComfyUI-MKnode.git
pip install -r ComfyUI-MKnode/requirements.txt
```

重启 ComfyUI 即可。本包绝大多数节点不需要额外依赖；只有「MK-遮罩裁剪 / MK-裁剪恢复」用到了 OpenCV，ComfyUI 本体不强制安装它，所以 `requirements.txt` 里显式声明了 `opencv-python`（装过会自动跳过）。

## 节点参数

### MK-加载图像

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 从 input 目录选择，支持直接上传 |
| 缩放模式 | 禁用 | `禁用` 保持原尺寸；`按总像素` 按目标总像素等比缩放 |
| 目标总像素 | 1 | 单位为**百万像素(MP)**，`1 MP = 1024×1024`。范围 0.01 ~ 16 |
| 尺寸倍数 | 1 | 缩放后宽高就近对齐到该值的整数倍（= 官方的「分辨率步数」），1 表示不对齐 |
| 缩放算法 | lanczos | nearest-exact / bilinear / area / bicubic / lanczos |

输出：`图像`、`遮罩`、`宽度`、`高度`。

> `禁用` 模式下的输出与官方 LoadImage **逐元素完全一致**，可直接替换现有工作流中的加载节点。

**「按总像素」与官方「缩放图像（像素）」完全一致**

缩放公式逐行复刻官方 `ImageScaleToTotalPixels`，所以**同样填「1.00 MP + 分辨率步数 32」，两个节点输出的尺寸一模一样**：

```
total    = megapixels * 1024 * 1024        # 1 MP = 1,048,576 像素
scale_by = sqrt(total / (w * h))
width    = round(w * scale_by / steps) * steps
height   = round(h * scale_by / steps) * steps
```

| 原图 | MP | 步数 | 官方输出 | 本节点输出 |
| --- | --- | --- | --- | --- |
| 1000×800 | 1.00 | 1 | 1145×916 | 1145×916 |
| 1000×800 | 1.00 | 32 | 1152×928 | 1152×928 |
| 1000×800 | 1.50 | 32 | 1408×1120 | 1408×1120 |
| 1920×1080 | 1.00 | 32 | 1376×768 | 1376×768 |
| 1920×1080 | 2.00 | 8 | 1928×1088 | 1928×1088 |
| 768×1344 | 1.50 | 32 | 960×1664 | 960×1664 |
| 1234×567 | 1.50 | 32 | 1856×864 | 1856×864 |

- 宽高是**各自就近对齐**到步数倍数（不是等比格子搜索），所以可能有 1~3% 的比例偏差 —— 这一点也和官方相同。
- 想要完全等比、只靠 `步数 = 1`：1000×800 → 1145×916，比例偏差 0.02%。
- 官方的 `resolution_steps` 是高级参数（默认 1），本节点的「尺寸倍数」同样默认 1。

### MK-图像选择器

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 待选择的图像，多张时平铺显示在节点上 |
| 模式 | 等待选择 | `等待选择` 执行时暂停，点选后点「确认选择」继续；`自动通过` 不暂停，直接放行全部图像 |

输出：`选中图像`、`选中索引`（逗号分隔）。

点选图像后按钮会显示已选数量，点「确认选择」继续；点「取消运行」中断整个执行。

候选图 ≤ 4 张时，预览区按**图片原始宽高比**自动排布：横图排成横卡、竖图排成竖卡，同一行基线对齐、整行铺满宽度，图片完整显示不裁切；≥ 5 张时回到小方格 + 滚动。

### MK-图像对比

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像A | — | 对比的基准图，也是「图像A」输出的内容 |
| 图像B | — | 参照图，只用于显示 |

输出：`图像A`（把输入 A 原样透传）。

- 与官方 `Compare Images`（`ImageCompare`）同款交互：执行后两张图叠在节点上，鼠标在预览区左右移动即可拖动分割线，左侧看 A、右侧看 B，拖动范围自动夹在 0.5%～99.5%。
- 与官方的唯一差别是**多了一个 IMAGE 输出**，可以把 A 图接着往下传（官方节点只有对比、没有输出）。
- 两张输入都是**可选**的：只接 A 就只显示 A（不裁切、不显示把手）；只接 B 则输出为空、仅作预览。
- 批量图（同一输入里多张）会在面板顶部出现 `图像A` / `图像B` 的 `‹ 1 / 3 ›` 翻页条，只在对应输入超过 1 张时显示。

### MK-图像裁剪

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 待裁剪的图像，支持批量（批次内每张图用同一组参数） |
| 宽度 | 256 | 裁剪宽度，步长 8。超过原图宽度时自动收敛到原图宽度 |
| 高度 | 256 | 裁剪高度，步长 8。超过原图高度时自动收敛到原图高度 |
| 位置 | 左上角 | 左上角 / 上方居中 / 右上角 / 右侧居中 / 右下角 / 下方居中 / 左下角 / 左侧居中 / 居中 |
| X 轴偏移 | 0 | 在基准位置之上再横向移动，可为负 |
| Y 轴偏移 | 0 | 在基准位置之上再纵向移动，可为负 |

输出：`图像`（裁剪结果）、`X 坐标`、`Y 坐标`（实际裁剪起点，已过边界检查）。

- 裁剪尺寸超过原图时自动收敛到原图尺寸，不会报错。
- 越界时把裁剪框夹回图像范围内，**但不会据此重算尺寸**——因此负偏移会让结果变小，而不是把窗口平移出去。这与上游 `ImageCrop+` 的行为一致，刻意保留。

> 裁剪节点迁移自 [ComfyUI_essentials](https://github.com/cubiq/ComfyUI_essentials) 的 `ImageCrop+`。
> 为兼容源包已保存的工作流，节点 id（`MK_ImageCrop`）、内部输入 id（`图像`、`宽度`…）
> 与「位置」的选项值都保持中文原样，与包内其他节点「内部 id 用英文」的约定不同。

### MK-自适应百万像素

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 用来读取像素数的图像。多帧批次按第一帧的宽高计算 |
| 最小百万像素 | 1.0 | 下限，范围 0.01 ~ 64，步长 0.01 |
| 最大百万像素 | 4.0 | 上限，范围 0.01 ~ 64，步长 0.01 |

输出：`百万像素`（FLOAT，保留 2 位小数），判定规则：

| 情况 | 输出 |
| --- | --- |
| 图像总像素 < 最小 | 最小值 |
| 图像总像素 > 最大 | 最大值 |
| 落在两者之间 | 图像本身的总像素（换算成 MP） |
| 最小 == 最大 | 该值（区间退化成一个点） |

例：最小 1 / 最大 4 时，640×640（0.39 MP）→ `1`；1024×1024（1.00 MP）→ `1`；1080×1928（1.99 MP）→ `1.99`；2048×2048（4.00 MP）→ `4`。

> 单位是**百万像素(MP)**，**1 MP = 1024 × 1024 = 1,048,576 像素**，与官方「缩放图像（像素）」
> （`ImageScaleToTotalPixels`）的 MP 口径一致 —— 输出直接接给官方缩放节点不会偏。
> 也和「MK-加载图像 → 缩放模式=按总像素」同一口径，可以接过去让缩放跟着图片自适应。
> 输出固定保留 **2 位小数**（四舍五入），避免出现 `2.08224` 这种长尾巴；需要更细的精度改 `nodes/adaptive_megapixels.py` 里的 `_OUTPUT_DIGITS` 即可。
> 最小 > 最大时会自动换位，不会出现空区间。

### MK-自适应最长边

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 用来读取尺寸的图像。多帧批次按第一帧的宽高计算 |
| 最小分辨率 | 512 | 下限（像素），范围 64 ~ 16384 |
| 最大分辨率 | 2048 | 上限（像素），范围 64 ~ 16384 |

输出：`最长边`（INT），判定规则（最长边 = max(宽, 高)）：

| 情况 | 输出 |
| --- | --- |
| 最长边 < 最小分辨率 | 最小分辨率 |
| 最长边 > 最大分辨率 | 最大分辨率 |
| 落在两者之间 | 图像本身的最长边 |
| 最小 == 最大 | 该值（区间退化成一个点） |

例：最小 512 / 最大 2048 时，400×300 → `512`；1080×1928 → `1928`；2000×3000 → `2048`。

> 和「MK-自适应百万像素」是一对：那个按**总像素**算（输出 FLOAT，适合「按总像素缩放」），
> 这个按**长边**算（输出 INT，适合「缩放到长边 N 像素」这类参数）。
> 输出是整数像素，最小 > 最大时同样会自动换位。

### MK-图片背景移除

一键抠图，输出带透明通道的图像、遮罩，以及遮罩的可视化图。迁移自 ComfyUI-RMBG 的
「去除背景 (RMBG)」，4 个模型后端与全部参数完整保留，接口改写为 V3 API。

模型放在 `ComfyUI/models/RMBG/<模型名>/`（与源插件一致，已有缓存可直接复用）；
文件缺失时会尝试从 HuggingFace 下载，网络不通则报错并列出需要的文件名。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 要抠图的图片，支持批次 |
| 模型 | RMBG-2.0 | RMBG-2.0 综合最稳；BEN2 对发丝细节更好；INSPYRENET 对纯色背景更快 |
| 灵敏度 | 1.0 | 调低收缩前景，调高吃掉更多边缘过渡；1.0 为模型原始输出 |
| 处理分辨率 | 1024 | 推理时缩到这个尺寸再算遮罩，越高越准也越吃显存（自动对齐 128） |
| 遮罩羽化 | 0 | 对遮罩边缘做高斯模糊 |
| 遮罩偏移 | 0 | 正数外扩（多留边），负数内缩（少留边） |
| 反转输出 | 关 | 图像与遮罩一起反转，用于「保留背景」 |
| 优化前景 | 关 | 用前景颜色回收算法处理边缘过渡，减少白边，会慢一些 |
| 卸载模型 | 关 | 跑完把模型移出显存；连续处理多张时建议关闭以复用 |
| 背景 | Alpha | Alpha 输出透明图；Color 合成到「背景色」上 |
| 背景色 | #222222 | 支持 `#RRGGBB` 与 `#RRGGBBAA`，用 ComfyUI 原生取色器 |

输出：`图像`（Alpha 模式为 4 通道）、`遮罩`、`遮罩图`（三通道可视化）。

### MK-遮罩裁剪 / MK-裁剪恢复

一对配合使用的节点：前者按遮罩把主体裁出来送去重绘/放大，后者把结果精确贴回原位。

**MK-遮罩裁剪**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 / 遮罩 | — | 遮罩非零区域即主体，裁剪框围着它算；多帧只取第一张 |
| 遮罩填充 | 关 | 先把遮罩内部的孔洞填实再算范围 |
| 扩展系数 上/下/左/右 | 1.4 | 按「遮罩最短边 × 系数」向外扩，1.0 不扩，1.4＝往外 40% |
| 输出尺寸 | 原像素 | `原像素` / `原像素1：1`（最小外接正方形）/ `自定义宽高`（等比缩放后居中补黑） |
| 自定义宽 / 高 | 1024 | 只填一个时按长边等比推导另一个（另一个填 0） |
| 倍数取整 | 8 | 输出宽高**向上**取整到该值的倍数，避免 VAE 分块裁掉像素；1 = 不取整 |

输出：`接缝`（SEAM，给恢复节点用的上下文）、`裁剪图像`、`裁剪遮罩`。

**MK-裁剪恢复**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 接缝 | — | 接裁剪节点的 `接缝` 输出 |
| 裁剪图像 | — | 处理过的裁剪图 |
| 遮罩扩展百分比 | 5 | 融合前把遮罩向外扩多少（遮罩宽高平均值的百分比） |
| 遮罩羽化百分比 | 5 | 融合边缘羽化多少（同口径） |
| 裁剪遮罩（可选） | — | 重绘后生成的新遮罩，比原遮罩更贴合被改动区域 |
| 背景图像（可选） | — | 换一张同尺寸底图贴回（例如先做了整图放大） |
| 颜色还原强度（可选） | 1.0 | 与原图同位置像素比对，统一校正明度与颜色；0 关闭 |

输出：`图像`（与原图同尺寸）。

> 迁移自 Goohaitools 插件包（`Goohaitools-comfyui`）的「孤海-遮罩裁剪V2 / 孤海-裁剪恢复」，
> 只改了类名、节点 id 与分类，**算法与参数逐行保持一致**。
> 自定义类型名仍是 `SEAM`、接缝里的键名也没动，所以本包节点可以和原包节点互相接线。

### MK-遮罩是否为空

判断一张遮罩里到底有没有东西，输出 `BOOLEAN`，用来做条件分支、跳过空分支。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 遮罩 | — | 要判断的遮罩；多帧批次按整批一起统计（总面积 = B×H×W） |
| 过滤最小值 | 3.0 | 有效面积占全图的百分比阈值（0–10）。像素值 > 0.5 才算有效，占比 ≥ 该值输出 True；设为 **0** 时不计算面积，只要有一个有效像素就输出 True |

输出：`是否有遮罩`（True = 非空，False = 空遮罩或有效面积不足）。

> 迁移自 Goohaitools 的「孤海遮罩检测」（节点 id `GuHaiMaskDetect`），判定逻辑一字未改：
> 0.5 的像素阈值、按面积占比过滤、阈值为 0 时短路。
> 改名：节点 id `MK_MaskIsEmpty`、显示名 `MK-遮罩是否为空`、分类 `MK节点`；
> 输入 id 改为英文（`mask` / `min_area_percent`），中文显示名与提示走 Schema。
> 输出语义保持原样：**True = 有遮罩（非空）**，False 才是空。

### MK-图像合并（遮罩）

把「覆盖图」按遮罩合成到「背景图」上。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 背景图 / 覆盖图 | — | 输出尺寸与背景图一致 |
| 透明度 | 1.0 | 整体不透明度，乘进遮罩；0 = 直接输出背景图 |
| 遮罩扩展 | 0 | 正数把遮罩向外扩（像素），负数向内收 |
| 模糊半径 | 0 | 对遮罩做高斯模糊，软化拼接边缘 |
| 匹配图像大小 | 关 | 开＝覆盖图拉伸到背景大小；关＝保持原尺寸居中（只替换遮罩区域） |
| 遮罩（可选） | — | 决定覆盖图贴到哪些位置；不接则整块覆盖图都参与 |

输出：`图像`（与背景图同尺寸）。

> 迁移自 Goohaitools 插件包的「孤海-图像合并（遮罩）」，只改了类名/节点 id/分类，**算法逐行一致**。
> 两个上游行为提醒（均未改动）：
> 1. 内部全程 RGBA 合成，输出是 **4 通道**（带 alpha）；接只认 3 通道的节点（如 VAE 编码）前先去 alpha。
> 2. `匹配图像大小` 关掉且**不接遮罩**时，四周会变成透明（黑），建议始终接遮罩使用。

### MK-提示词拼接

| 参数 | 默认 | 说明 |

### MK-提示词预设图库

一个文本框 + 下方两个按钮：「预设图库」和「当前提示词存为预设」。

- **预设图库**：弹出居中面板（约 1200×800，随窗口自适应），左侧分类栏，右侧缩略图网格
  （**预览图下面就是提示词**），点任意一张卡片会把该条目的提示词**覆盖写入文本框并同时复制到剪贴板**。
- **当前提示词存为预设**：在按钮上方弹出分类选择，选一个分类就把文本框内容存成纯文本预设；
  没有任何分类时会自动新建「未分类」并存进去。保存结果直接显示在按钮文字上（`✓ 已存到「…」`），约 1.8 秒后恢复。

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| 提示词 | 空 | 多行文本框，支持动态提示词语法；点卡片后可被覆盖 |

输出：`提示词`（原样透传文本框内容）。

左栏结构：

- **全部图片**：内置素材 + 以后的自有素材，按需分批加载（滚动到底继续追加）
- **写真图片**：内置分组，只读（有「内置」标记，不提供删除/编辑），下挂 11 个子分类：
  萌妹 / 卧室 / 浴室 / 客厅·沙发 / 影棚·纯色 / 泳池·海边 / 城市·街拍 / 自然·公园 / 车内 / 室内其他 / 综合其他
  （「萌妹」是手工分类，300 张图 + 对应提示词，用 `tools/import_gallery_html.py` 追加维护）
- **分类**：自己的分类，可任意嵌套 —— `＋` 新建顶级分类（回车确认、Esc 取消）；
  **在分类行上右键**可以「新建子分类 / 重命名 / 删除分类」，悬停也有 `✕` 删除（底部内联确认，连同子分类一起删）。
  点**一级分类会把它的所有子分类素材汇总显示**（父分类自己的条目排在最前），卡片上会标出所属子分类；
  任何分类都能「＋ 添加素材」，新素材加到**当前选中的那个分类本身**。
  选中分类后，右侧网格第一格是「＋ 添加素材」，可以填提示词、可选配一张图；
  在素材卡片上**右键**可以改提示词、移动到别的分类、或删除；也可以直接把卡片**拖到左侧的分类行**上完成移动。

**自建分类和素材都存在插件目录之外**（更新/重装插件不丢）：

```
<ComfyUI>/user/default/MKnode/Prompt Preset/
    tree.json                分类树（可嵌套）
    <分类 id>/items.json     该分类的素材条目
    <分类 id>/0001.webp      素材图（上传后统一转 WebP，长边 320）
```

对应后端是 `mk_ppg_store.py` 注册的 `/mk_ppg/*`（tree / items / upload / rmcat / asset）。

删除分类是**真删除**：`rmcat` 直接把该分类目录连同 `items.json` 与全部素材图删掉，
不进回收站、不保留副本，也没有恢复入口，占用的空间当场归还。

内置素材放在 `web/ppg_data/`，由 `tools/build_ppg_templates.py` 从 HTML 汇总文件拆出来（可以传多个源，按顺序叠加）：

```bash
python tools/build_ppg_templates.py "第一份提示词汇总.html" "第二份.html"
python tools/build_ppg_templates.py --width 180 --quality 72 "第一份.html"   # 默认值，可调
python tools/build_ppg_templates.py --no-resize "第一份.html"                # 保留原始图片字节
```

产物是 `manifest.json`（分组与子分类清单）+ 每个分类一个 `cat_<id>.json`（提示词与缩略图路径）
+ `img/<分类>/v<源序号>/<序号>.webp`（缩略图，默认压到 180px 宽 / WebP q72，压完更大就保留原图）。
分类由提示词里的场景关键词加权打分得到，权重表就在脚本顶部的 `RULES` 里，改完重跑即可；
多个源里提示词完全相同的条目会按 md5 去重。重建时直接覆盖同名文件，不整目录删除，
若出现对不上的旧文件，脚本末尾会报数量（需自行清理）。

**往已有分类增量追加**（不动其它分类，可反复重跑）用 `tools/import_gallery_html.py`：

```bash
python tools/import_gallery_html.py --html "画廊.html" --cat-id mengmei --cat-name 萌妹
python tools/import_gallery_html.py --html "画廊.html" --cat-id mengmei --cat-name 萌妹 --width 180 --quality 72
python tools/import_gallery_html.py --html "画廊.html" --cat-id mengmei --cat-name 萌妹 --width 0   # 保留原始图片字节
```

它只重写 `cat_<id>.json` 与 `img/<id>/v1/`，再把该分类增量写进 `manifest.json`（放在清单最前）。
不走关键词分类、也不被 `build_ppg_templates.py` 重建覆盖的分类，登记在后者顶部的 `EXTRA_CATS` 里
（默认 `("mengmei", "萌妹")`：重建时只把它的 `cat_mengmei.json` 读回来挂进清单，条目与图片都不动）。

> 内置素材只读：不进工作流、不写节点 properties，面板里也没有删除/编辑入口。
> 面板配色全部走 ComfyUI 的 CSS 变量（`--comfy-menu-bg` / `--fg-color` / `--border-color` /
> `--primary` / `--destructive`），深浅主题都自动适配。

### MK-显存清理 / MK-内存清理

两个「透传 + 清理」节点：接什么就原样输出什么，清理是副作用，所以既能单独当一个执行节点用，
也能插在流程中间不打断连线。两者都声明为输出节点，并用时间戳指纹保证**每次排队都会真跑一次**，
不会被 ComfyUI 的缓存跳过。迁移自 Comfyui-Memory_Cleanup，已改写为 V3 API。

**MK-显存清理**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 卸载模型 | 开 | `unload_all_models()`，释放已加载模型占用的显存 |
| 清空缓存 | 开 | `gc.collect()` + `soft_empty_cache()`，并通知队列释放内存 |
| 输入 | 未接 | 任意类型，原样透传到输出 |

**MK-内存清理**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 清理文件缓存 | 开 | Windows 收缩系统文件缓存；Linux 走 `malloc_trim` |
| 清理进程内存 | 开 | 遍历所有进程 `EmptyWorkingSet`，权限不足的自动跳过 |
| 清理未使用DLL | 开 | 收缩 ComfyUI 自身工作集，归还暂时不用的 DLL 与页面 |
| 重试次数 | 3 | 重复清理的轮数，每轮间隔 1 秒（系统回收内存需要时间） |
| 输入 | 未接 | 任意类型，原样透传到输出 |

实测（本机 16GB / Windows）：单轮「全部开关打开」可用内存 11476MB → 11990MB，约释放 515MB。
非 Windows 平台只执行能做的部分，不会报错。

### MK-Qwen Image 2.1提示词增强

用 Qwen 官方的提示词增强模型（PE-T2I / PE-I2I）把一句话的请求扩写成完整的画面提示词。
两个模型是 Qwen3.5-VL 9B 的微调版本，在 ComfyUI 里就是普通文本编码器，所以本节点直接调用
ComfyUI 自带的 `load_clip` / `clip.tokenize` / `clip.generate`，**不需要 transformers，也不需要 llama-cpp**。

模型放在 `ComfyUI/models/text_encoders/`，节点会自动按文件名里的 `pe_t2i` / `pe_i2i` 列出：

- `qwen3.5_9b_qwen_image_2.1_pe_t2i.*.safetensors` —— 文生图
- `qwen3.5_9b_qwen_image_2.1_pe_i2i.*.safetensors` —— 图生图

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 提示词 | 空 | 要增强的原始描述。图生图时用 `<image1>`、`<image2>` 指代第几张参考图 |
| 任务模式 | 文生图 | 文生图走 PE-T2I 扩写；图生图走 PE-I2I 改写编辑指令 |
| 输出语言 | 中文 | 描述文字的语言。用户明确要求的画面文字、专有名词保持原文 |
| 文生图PE模型 | 自动列出 | 任务模式为文生图时使用 |
| 图生图PE模型 | 自动列出 | 任务模式为图生图时使用 |
| 最大生成token | 4096 | 思考 + 提示词共用的预算。官方示例：文生图 16256 / 图生图 24000 |
| 上下文长度 | 8192 | 单次调用总预算（提示词 + 生成），可生成量不会超过它 |
| 随机种 | 0 | 采样种子，同种子同输入结果稳定 |
| 生成后控制 | 随机 | 随机种下方的下拉：固定 / 递增 / 递减 / 随机（ComfyUI 自带控件） |
| 启用思考 | 开 | 两个官方模型都是带思考块训练的，关闭会掉质量 |
| 卸载模型 | 开 | 生成后卸载模型并清显存缓存；关闭则常驻，下次更快 |
| 参考图1~9 | 未接 | 图生图模式的参考图，最多 9 张，统一缩到长边 1280 再送模型 |

输出：`增强提示词`（STRING 纯文本，可直接接文本编码节点）。

> 采样参数按官方模型卡固定：temperature 1.0 / top_p 0.95 / top_k 20；文生图版额外加
> presence_penalty 1.5 抑制复读，图生图版不加。系统提示词用的是 Qwen 官方随 PE 模型发布的
> 提示词工程规则（见 `nodes/qwen_pe_prompts.py`），模型会先思考、再输出一行 JSON，
> 节点只取其中的 `rewritten_prompt`；JSON 被预算截断时有正则兜底。

### MK-任意切换

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 任意 01 ~ 任意 NN | — | 任意类型、任意数量的输入。连满当前输入后节点会自动补一个空槽 |

输出：`任意`（第一个非空输入的值）。全为空时输出空。

- 按输入从上到下的顺序取**第一个非空值**：`None` 算空，空字符串、`0`、空列表都**不算**空；
  若接进来的是 rgthree 的 CONTEXT（内部全是 `None`），也按空处理并跳过。
- 输出槽与所有输入槽的**类型跟着连线走**：接 IMAGE 就整体变成 IMAGE，接 MODEL 就变成 MODEL；
  上游也是「任意切换」（类型同样是 `*`）时会顺着连线继续往上找，直到找到具体类型。
- 输入槽会自动维护：末尾多余的空槽会被折叠，始终保留 5 个，最后一个接上线后再补一个新空槽。
- 什么都不接时输出槽显示为 `*`，可以接任何下游。

> 迁移自 [rgthree-comfy](https://github.com/rgthree/rgthree-comfy) 的 `Any Switch`，执行逻辑（取第一个非空、`is_none` 的判定）
> 与上游逐行一致；差别在于本包不做 `addConnectionLayoutSupport`（左侧/右侧输入布局切换），
> 且类型跟随改为只读「别人的槽位类型」，避免把自己的槽位类型写死后断线回不到 `*`。

### MK-禁用（忽略）多组 老年关怀版 / 青春版

两个节点功能完全一样（同一套分组扫描与开关逻辑），只差界面，按习惯挑一个用：

| | 老年关怀版 | 青春版 |
| --- | --- | --- |
| 节点 id | `MK_IgnoreGroups` | `MK_IgnoreGroupsYouth` |
| 界面 | 自绘面板：行更高、字更大 | ComfyUI 原生控件：每组一个开关 |
| 设置入口 | 右上角齿轮 / 右键菜单 | 原生「设置」按钮 / 右键菜单 |
| UI 缩放 | 有（0.5–5.0） | 无，尺寸走默认 |
| 开关颜色 | 可改（组名 + 开关） | 可改（默认 `#a89961`） |

**老年关怀版**：纯 UI 节点，没有输入输出。面板把当前画布的每个编组列成一行开关（只列**至少含一个节点**的组，嵌套子组算父组成员）：

- 打开 = 组内节点恢复启用（mode 0）；关闭 = 按设置切到**绕过 Bypass**（mode 4，输入原样透传给输出）
  或**禁用 Mute**（mode 2，执行时直接跳过）；
- 顶部齿轮，或在节点上右键选「🎮 MK-禁用（忽略）多组 设置」，打开设置：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 路由控制 | 绕过 | 关闭一组时用 Bypass（ctrl+b）还是 Mute（ctrl+m） |
| 关键词筛选 | 空 | 只显示标题包含该词的组，留空 = 全部 |
| 颜色筛选 | 无 | 选项取自画布里真实存在的组颜色，另含「透明色」 |
| 切换模式 | 默认 | 默认 = 各组独立开关；始终开启1个 / 最多开启1个 = 组间互斥 |
| 排序 | 按位置 | 按位置（从上到下、从左到右）/ 按首字母 |
| UI组件大小 | 1.0 | 0.5–5.0，面板行高、字号、开关同比缩放 |
| 主题颜色 | `#a89961` | 组名与开关高亮色 |
| 包含子图分组 | 开 | 是否把子图内部的编组也列出来 |

- **支持子图**：节点放在子图里时，列出的是那张子图的编组；节点在根图时，除了根图编组，
  还会把画布上**实际用到的子图**内部的编组一起列出来（**行上只显示组名**，不加子图前缀）。
  子图里那部分改的是子图定义，同一子图的所有实例一起生效；不想要可以关掉「包含子图分组」。
- 状态实时同步：在别处用 ctrl+b / ctrl+m、新增或改动分组后，面板会在 0.5 秒内对齐；
- 打开父组会连同嵌套子组一起打开，避免面板与实际状态对不上；
- 设置随工作流保存（存在节点 properties 的 `mk_ig_*` 键里），换机器打开工作流仍然生效。

> 迁移自 GoohaiTools-comfyui 的「忽略多组 孤海」（节点 id `忽略多组孤海`），功能与交互逐项保留：
> 分组收集（含嵌套）、三档切换模式、关键词 / 颜色筛选、两种排序、面板缩放与主题色、外部状态回灌、
> Nodes 2.0 下的 DOM 重挂。改名与隔离：节点 id `MK_IgnoreGroups`、显示名 `MK-禁用（忽略）多组老年关怀版`、
> 扩展名 `Comfyui_MKnode.IgnoreGroups`、属性键 `mk_ig_*`、DOM 与 CSS 前缀 `mk-ig-*`，与源插件同装互不干扰。

**青春版**：功能同上，界面换成 ComfyUI 原生控件：

- 每个编组 = 一个原生开关（`toggle`），开着显示「开」、关着显示「关」；节点高度随分组数量自动伸展；
- 设置入口是节点上的**「设置」按钮**（右键菜单里也有一份），不再有齿轮图标；
- 设置项与老年关怀版相同，唯独**没有「UI组件大小」**（青春版不放大）；
  另外带一个「开关颜色」：原生 toggle 只会跟随全局主题，暗色皮肤下几乎看不出开没开。两种渲染都照顾到：
  画布模式下给开关套一层自绘（开 = 自定义颜色 + 实心圆点，关 = 中性灰）；
  Nodes 2.0（Vue 渲染）下开关是「关 / 开」分段按钮，改用一段只作用于本节点的 CSS 着色；
- 节点宽高走 ComfyUI 默认行为，可正常拖拽调整，没有额外的缩放设置。

> 两个版本共用 `web/mk_ignore_groups_core.js` 里的分组扫描与状态判定，只是换了渲染层：
> 老版自绘 DOM，青春版用 `addWidget("toggle")` / `addWidget("button")`。开关状态同样存在节点
> properties（`mk_ig_*`），widget 设为 `serialize:false`，所以分组增减不会打乱 `widgets_values`。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 图像 | — | 要放大并切块的图片 |
| 成品百万像素 | 4.0 | 成品总像素（MP）。填 **0** 表示保持原图尺寸，只做一次轻量重绘 |
| 放大模型 | 不接 | 可选。切块前先用它放大一遍；不接则用 lanczos 普通插值 |
| 单块百万像素 | 2.0 | 模型一次最多重绘多少。Qwen Image 2.1 / Krea 2 用 2，SDXL 用 1 |
| 重叠像素 | 128 | 相邻分块共享多少像素，拼接时在这一条上羽化 |
| 对齐倍数 | 32 | 每块宽高对齐到该倍数；Qwen Image 2.1 必须 32 |
| 最大放大倍数 | 8.0 | 小图最多重绘到自身 MP 的这个倍数，再往上只能普通放大 |

输出：`分块`（**列表**，下游节点会为每块各跑一次）、`分块信息`（连给分块合并）、`原图参考`、`成品宽`、`成品高`、`报告`（本次对这张图做了什么）。

**MK-分块合并**

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 分块 | — | 重绘后的分块，顺序需与分块输出一致；尺寸变了会被适配回原位置 |
| 分块信息 | — | 「MK-图像分块」输出的分块信息 |
| 保色 | 1.0 | 1 = 每块对齐到原图同一块的颜色；调低让模型配色透出；0 = 关闭 |

输出：`图像`（成品图；输入是多张图时输出同样是一组图）。

> 分块尺寸来自原图比例与百万像素预算，规则与「图像分块」的规划一致：重绘尺寸不超过原图 MP 的「最大放大倍数」，
> 差额由 lanczos 补齐，因此小图不会被拉去重绘它本来没有的细节。`保色` 用 LAB 通道的直线拟合，
> 只跟随两张图共有的内容，老照片的噪点不会被当成颜色而放大饱和度。
> 迁移自 ComfyUI-AusBoss 的 Tiled Upscale / Tiled Upscale Stitch，已改写为 V3 API（NODE 2.0）：
> `io.ComfyNode` + `define_schema`，分块信息类型改为 `MK_TILE_STITCHER`。

### MK-多媒体素材加载 / MK-多媒体素材解包

一对配合使用的节点：前者把素材装好并**打包成一条总线**（画布上只有一根线），后者把总线**拆成 18 个素材口**直连参考生视频。

```
MK-多媒体素材加载 ──素材总线──> MK-多媒体素材解包 ──18 个素材口──> MK-Minimax H3多参考生视频
```

**MK-多媒体素材加载**

面板是 3×3 九宫格 + 3 个音频格 + 3 个视频格，每格左上角编号、右上角开关、右下角清除；
点格子选文件，也可以直接把文件拖进去。

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| 素材配置（`media_settings`） | 空槽位 | 面板自动维护的 JSON，随工作流保存，widget 已隐藏，一般不用手改 |

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| 素材总线 | `MK_REF2VA_BUS` | 19 个槽位（9 图 + 3 视频 + 3 视频原声 + 3 音频）打包成的一条总线，只接得进「MK-多媒体素材解包」 |

**MK-多媒体素材解包**

只有一条总线输入，输出 18 个素材口，**口名与本包「MK-Minimax H3多参考生视频」的输入口逐字一致**，一根线一个口直连：

| 输出口 | 类型 | 下游对应输入 |
| --- | --- | --- |
| `ref_image_1` ~ `ref_image_9` | IMAGE | 参考图 1~9（提示词 `<Picture i>`） |
| `ref_video_1` ~ `ref_video_3` | IMAGE | 参考视频 1~3（`<Video k>`） |
| `ref_video_audio_1` ~ `ref_video_audio_3` | AUDIO | 参考视频音频 1~3 |
| `ref_audio_1` ~ `ref_audio_3` | AUDIO | 参考音频 1~3（`<Audio j>`） |

总线类型 `MK_REF2VA_BUS` 是自定义类型：只能这两个节点之间互连，接别的类型直接连不上，
不会出现「接错了跑一半才发现」。它与上游 JZL 的 `JZL_REF2VA_BUS` 是两套，同装也不会串线。

每个格子的参数（点格子右下角的小按钮开对话框，◀ ▶ 可按住连续微调）：

| 类型 | 参数 | 说明 |
| --- | --- | --- |
| 图片 | 开关 | 关掉的槽位不装载，解包后对应口为 `None` |
| 图片 | 缩放模式 | `禁用`（默认，原图直出）/ `按总像素` |
| 图片 | 目标总像素 | 只在「按总像素」时出现；单位 **MP（百万像素）**，**1 MP = 1024×1024**，默认 `1.00`，范围 0.01 ~ 64。档位 `0.5/1/2/4/8` 一点即填 |
| 图片 | 尺寸倍数 | 只在「按总像素」时出现；公式与官方 `ImageScaleToTotalPixels` 的 `resolution_steps` 完全一致（`round(边长×scale/步数)×步数`），`1`（默认）= 不对齐，范围 1 ~ 256。档位 `1/8/16/32/64` 一点即填 |
| 图片 | 缩放方式 | 只在「按总像素」时出现；与 ComfyUI 官方 `upscale_method` 同一套：`邻近-精确` / `双线性插值` / `区域` / `双三次插值` / `Lanczos（高质量抗锯齿）`（默认） |
| 音频 | 「音频裁剪」面板 | 点格子右下角的「音频裁剪」打开：波形图上拖动框选区间、拖两端手柄微调、`▶ 试听` 只放选中那段；下方两个数字框（开始时间 / 音频时长，秒，步长 0.01，0 = 到结尾）与图形双向联动 |
| 视频 | 强制帧率 | 0 = 保持原帧率；大于 0 时按该帧率重采样 |
| 视频 | 跳过帧数 | 在改帧率之后计数，从第 N 帧开始取 |
| 视频 | 输出宽度 / 高度 | 0 = 原尺寸；只填一边时另一边按比例并偶数对齐 |
| 视频 | 帧数上限 | 0 = 不限（后端另有 6000 帧安全上限防吃光内存） |

**图片怎么缩放**：只有「禁用」和「按总像素」两种状态，等比缩放、比例与原图完全一致，不做尺寸对齐、也不裁边。

| 设置（1000×800 = 0.8MP 的图） | 输出 |
| --- | --- |
| 禁用 | `1000×800`（原图直出） |
| 按总像素 `1.00` MP | **`1118×894`**（约 100 万像素） |
| 按总像素 `4.00` MP | `2236×1789` |
| 按总像素 `0.50` MP | `791×632` |
| 目标面积正好等于原图（0.80MP） | 原图直出，不重采样 |
| 横长条 3000×1000 → `1.00` MP | `1732×577`（3:1 比例保持） |

- 目标值过大有硬上限：单边 ≤ 8192、总量 ≤ 64MP。超了按比例压回来，并在状态栏 / Toast 里提示「目标尺寸过大，已按上限压到 WxH」，不会把 9 张图一起送进 OOM。
- **三组素材可以分别折叠**：点分组标题（`🖼️ 参考图` / `🎧 参考音频` / `🎬 参考视频`）即可收起或展开，
  **参考音频和参考视频默认折叠**（平时用不到），节点高度会跟着内容自动贴合。
  折叠**只影响显示，不影响装载** —— 收起来的槽位照样读盘、照常输出；折叠头右侧会显示
  `N 个已载入`（有关掉的会写成 `N 个已载入 · M 个已关闭`），收起状态下也能看出这组有没有素材。
  折叠状态存在节点 properties 的 `mk_h3m_folded` 里，随工作流保存，重开工作流保持上次的状态。
- **音频裁剪是图形化的**：打开「音频裁剪」会拉到服务端解码出来的波形（`/mk_h3/audio_waveform`，600 个峰值桶），
  在波形上拖动即可框选区间、拖两端手柄微调、点空白重新框选；`▶ 试听` 只播选中那段，播到末尾自动回到起点。
  波形由服务端解（soundfile 优先、退 PyAV），所以 m4a / aac / opus / wma 这些浏览器不一定支持的格式也能画出来。
  波形按 `path + mtime + size` 缓存，同一个素材第二次打开是瞬时的。
- **缩放方式**与 ComfyUI 官方 `upscale_method` 同名同序，内部映射到 PIL 滤镜：`邻近-精确`→NEAREST、`双线性插值`→BILINEAR、`区域`→BOX、`双三次插值`→BICUBIC、`Lanczos`→LANCZOS。缩小选 Lanczos / 区域最稳，放大选 Lanczos / 双三次；`邻近-精确`不产生新像素，缩小时会留块状边界。
- **视频音轨跟着画面裁**：跳过帧数 / 帧数上限换算成秒，原声只取与画面相同的区间，不会出现「画面只 6 帧、声音却 3 秒」。
- **素材被同名覆盖会自动重跑**：`IS_CHANGED` 把每个素材的 `mtime + size` 拼进指纹，不会吃上一次的缓存结果。
- **素材落在 `ComfyUI/input/MKnode/h3/<image|video|audio>/`**，节点里存的是 input 相对路径，工作流换机器只要素材跟着 input 走；从 JZL 插件搬过来的旧工作流（路径写成 `jzl/image/xxx.png`）也能直接读。
- 未启用 / 未上传 / 文件丢失的槽位在总线里是 `None`，解包后等于该口没连线；文件丢失会在状态栏和右下角 Toast 里报出来。
- 面板配色自带一套 `--mk-h3m-*` 变量（深/浅主题各一套），不依赖任何外部主题文件。

> 迁移自 [ComfyUI-JZL-MiniMax-H3](https://github.com/wjluoxiao/ComfyUI-JZL-MiniMax-H3) 的「📥 MiniMax 素材加载」（`JZL_MiniMaxH3MediaLoader`）：
> 装载逻辑（EXIF 旋转、PyAV 抽帧、强制帧率 / 跳帧 / 宽高 / 帧数上限、音轨同步裁切、音频切片、脏数据钳制）逐行保留。
> 总线仍是「打包 → 解包」两段式（与上游同构），只把类型换成 `MK_REF2VA_BUS`、解包端的口名对齐到本包参考生视频节点的输入口。
> 上传与预览端点改名为 `/mk_h3/*`（`mk_h3_media_store.py`）。

## 说明


- 图像加载直接复用官方 `LoadImage` 的加载逻辑，保证 pyav / Pillow 两条路径（含动画 WebP 回退、EXIF 旋转、alpha 转遮罩）与上游一致。
- 图像选择器迁移自 [Comfyui_LG_Tools](https://github.com/LAOGOU-666/Comfyui_LG_Tools) 的 ImageSelector，交互逻辑保持一致，并删除了 `keep_last_selection` 模式；已改用 V3 API（`io.ComfyNode`），前端由 canvas 绘制改为 DOM 组件，因此在旧版 LiteGraph 与 Nodes 2.0（Vue 渲染）下都能正常选图。
- 图像对比对齐官方 `ImageCompare`（`comfy_extras/nodes_image_compare.py`）的实现：同样用 `PreviewImage` 把两批图落成临时文件、以 `ui.a_images / ui.b_images` 回传前端，前端按同款「叠图 + 分割线」交互渲染；差别只在于新增了一个 IMAGE 输出，且前端不复用官方 `imagecompare` widget（那个 widget 只对 `comfyClass === "ImageCompare"` 的节点接线），改为本包自绘的 DOM 组件。
- 图像裁剪迁移自 [ComfyUI_essentials](https://github.com/cubiq/ComfyUI_essentials) 的 `ImageCrop+`，坐标计算与边界处理逐行保持上游行为。
- 提示词拼接迁移自 [ComfyUI-Easy-Use](https://github.com/yolain/ComfyUI-Easy-Use) 的 `easy promptConcat`，节点 id 与内部输入 id 保持原样以兼容源包工作流。
- 遮罩是否为空迁移自 Goohaitools-comfyui 的「孤海遮罩检测」，判定逻辑未改，仅改名与英文输入 id。
- 禁用（忽略）多组迁移自 GoohaiTools-comfyui 的「忽略多组 孤海」，面板逻辑（分组收集、三档模式、筛选排序、缩放换色、状态同步）逐项保留，仅做命名隔离；后端只注册一个空节点给前端挂面板。
- 新增节点使用 V3 API（`io.ComfyNode` / `io.Schema` / `io.NodeOutput`）；提示词拼接（依赖未声明的动态输入）保留 V1 写法。
- Nodes 2.0 用 Vue 渲染节点，不会再调用 `onDrawBackground` / `onMouseDown` 等 LiteGraph 画布钩子。本包的前端交互统一用 DOM 组件（`addDOMWidget`）实现，两种渲染模式下行为一致。
